# Учебный центр v2: шаги этапа, ситуации, практика и дневник — спецификация

**Статус:** дизайн одобрен владельцем 11.10.2026 по макетам (m1–m7); спецификация на проверке.

**Основа:** `docs/superpowers/specs/2026-10-11-uchebny-tsentr-design.md` (MVP) — всё, что там не изменено ниже, остаётся в силе: статические индексируемые страницы, vanilla JS, прогресс только в браузере, без регистрации, без нового отслеживания, работа в ветке/PR без выкладки.

## Цель

Сделать Учебный центр функциональнее и удобнее: посетитель не только читает гайды по порядку, а проходит в каждом этапе четыре шага — читает, разбирает игровые ситуации, проверяет себя тестом и применяет навык в реальном матче, записывая результат. Раскладка страниц перерабатывается под эти шаги и под быстрый возврат к следующему действию.

## Решения владельца

- Новые механики: **ситуационные задачи** и **практика в матче с дневником**. Карточки терминов, итоговый экзамен и достижения — не в этой версии.
- Раскладка — вариант «одна страница маршрута, этап — карточка из четырёх шагов» (одобрен по макетам). Отдельных страниц этапов нет.

## Что видит посетитель

### Страница маршрута (`/academy/beginner/`, `/academy/rank-up/`)

1. **Шапка маршрута.** Слева: «Учебный центр · маршрут», название, описание, чипы (этапы, уроки, ситуации, время чтения). Справа — блок «следующий шаг»: кольцо общего прогресса в процентах, подпись «N из M шагов · этапов завершено K», крупная кнопка «Следующий шаг» с подписью, куда ведёт (например «Этап 3 · Разбери ситуацию»), и ссылка «Сбросить прогресс маршрута».
2. **Навигация по этапам.** На ширине ≥ 981px — закреплённая слева панель «Этапы маршрута»: номер-кружок (✓ для завершённого, золотой контур для текущего), название, строка состояния («Завершён», «Шаг 2 из 4 · ситуации», «5 уроков»); внизу — число записей в дневнике маршрута. На ширине ≤ 980px панель заменяется горизонтальной прокручиваемой лентой этапов с теми же кружками.
3. **Этап — сворачиваемая карточка** (`<details>`). В свёрнутом виде: «Этап N», название, чипы состояния «Чтение x/y · Ситуации x/y · Тест z% или — · Практика x/y», для завершённого — «✓ Завершён» и зелёная рамка. Открыт по умолчанию этап, в котором находится следующий шаг; остальные свёрнуты.
4. **Внутри этапа:** короткое вступление и четыре шага-вкладки (номер или ✓, название, счётчик):
   - **Прочитай** — уроки строками: отметка «пройдено», название, одна строка описания, время чтения, кнопка «Открыть» (ведёт на `/guide/<slug>/`). Следующий непройденный урок подсвечен пометкой «Следующий».
   - **Разбери ситуацию** — по одной ситуации за раз («Ситуация 1 из 2»): контекст (минута, линия, роль), описание, три варианта. После выбора: выбранный вариант помечен «Твой выбор» (красный, если не лучший) с разбором, лучший — «Лучше» (зелёный) с разбором, ссылки на гайды-источники; выбор можно изменить. Навигация «← Ситуация 1» / «Ситуация 2 →» / «К тесту →».
   - **Проверь себя** — существующий тест этапа без изменений поведения.
   - **Сыграй и запиши** — две колонки (на узком экране — одна): «Задания на следующий матч» — чек-лист из практических заданий уроков этапа; «Дневник этапа» — поле до 500 символов со счётчиком и подписью «только в этом браузере», кнопка «Сохранить запись», список записей этапа с датой и кнопкой удаления.

### Главная Учебного центра (`/academy/`)

1. Заголовок и вступление (обновлённый текст: в каждом этапе уроки, ситуации, тест и задания на матч).
2. **Панель «Продолжить»** — только если в браузере есть прогресс: кольцо прогресса рядом с текстом (в том числе на телефоне), «Продолжить «<маршрут>»», подпись следующего шага, кнопка. Берётся маршрут, который изменялся последним.
3. **Как устроено обучение** — четыре плитки «Читай / Разбирай / Проверяй / Играй» с одной строкой пояснения; на телефоне сжимаются в одну строку из четырёх значков с подписями (без пояснений).
4. **Карточки маршрутов:** подпись аудитории («Для новичков» / «Для рейтинговых игр»), название, описание, полоса из пяти сегментов-этапов (завершён — зелёный, начат — наполовину золотой, не начат — пустой) с подписями этапов, строка фактов (без прогресса: этапы, уроки, ситуации, время; с прогрессом: «K из 5 этапов · N из M шагов · записей в дневнике»), кнопка («Начать маршрут» или «Продолжить: <шаг>»).

### Правки, замеченные на макетах

- Отметка пройденного урока и задания: галочка контрастная (тёмная на зелёном, жирная).
- На телефоне плитки «как устроено» не занимают экран (см. выше), кольцо в панели «Продолжить» стоит рядом с текстом.

## Правила прогресса

- **Шаги маршрута** = уроки + ситуации + один тест на этап + практические задания. Для «С нуля»: 18 + 10 + 5 + 18 = 51; для «Поднять рейтинг»: 19 + 10 + 5 + 19 = 53. Числа считаются из данных, не вписываются руками.
- Урок выполнен — отмечен «пройдено». Ситуация выполнена — выбран любой вариант (разобрана, даже если не лучший). Тест выполнен — отправлен полностью хотя бы раз (любой результат; лучший процент показывается). Задание выполнено — отмечено.
- **Этап завершён**, когда выполнены все его шаги всех четырёх типов.
- **Следующий шаг** — первый невыполненный по порядку: этапы 1→5, внутри этапа уроки → ситуации → тест → задания. Если всё выполнено — «Маршрут пройден», кнопка ведёт к началу маршрута.
- Неверный ответ в тесте или выбор не лучшего варианта в ситуации ничего не блокирует.

## Данные курса (`academy-content.js`)

- ID курсов, этапов, уроков и вопросов теста **не меняются** — от них зависит сохранённый прогресс.
- Урок сохраняет поле `practice`; оно теперь выводится в шаге «Сыграй и запиши» как задание чек-листа (ID задания = ID урока), а не в строке урока.
- Новое поле этапа `scenarios` — ровно 2 ситуации:
  - `id` (постоянный, `<moduleId>-s1`/`-s2`), `context` (короткая строка: минута, линия, роль), `prompt`, `options` — ровно 3 объекта `{ text, feedback }`, `bestIndex` (0–2), `sources` — 1–2 slug гайдов из `guide-content.js`;
  - если ситуация опирается на патч-зависимое число — поле `checked` (дата и патч проверки), как у вопросов теста.
- Ситуации пишутся по текстам связанных гайдов сайта: лучший вариант и разборы должны следовать из гайда; варианты — правдоподобные ошибки, а не очевидные глупости; ответы разнесены по позициям A/B/C. Тексты пишет Claude в этой сессии (ключей `tools/llm.py` в облачной среде нет) и подписывает это в PR; владелец просматривает до публикации.
- Сборщик (`tools/academy-render.js`) проверяет ситуации так же строго, как тесты, и останавливает сборку с ошибкой, называющей курс, этап и ситуацию: несуществующий гайд, не 3 варианта, пустой текст, `bestIndex` вне 0–2, повтор ID.

## Хранение в браузере

- Ключ `dotamate.academy.progress.v2`, форма:
  `{ version: 2, courses: { [courseId]: { completedLessons: string[], bestScores: { [moduleId]: number }, lastLessonId: string|null, scenarioChoices: { [scenarioId]: 0|1|2 }, practiceDone: string[], diary: [{ id, moduleId, date, text }], updatedAt: number } } }`.
- **Перенос с v1:** если v2 нет, а v1 (`dotamate.academy.progress.v1`) есть и корректен — отметки уроков, результаты тестов и последний урок переносятся, новые поля пустые; запись идёт в v2, ключ v1 не удаляется (откат безопасен).
- Валидация как в MVP: неизвестные ID, неверные типы, ответы вне 0–2, неконечные числа отбрасываются; повреждённые данные → пустой прогресс без падения.
- Дневник: текст до 500 символов, не более 30 записей на маршрут (при превышении удаляется самая старая с кратким уведомлением), выводится только через `textContent`. `id` записи — строка из времени и случайной части.
- Каждое изменение перечитывает хранилище перед записью; событие `storage` обновляет открытые вкладки (как сейчас). Недоступное или переполненное хранилище — работа в памяти и краткое предупреждение (как сейчас).
- Сброс маршрута очищает все поля только этого маршрута, включая дневник; текст подтверждения называет, что будет удалено.

## Без JavaScript и для поиска

- Весь текст уроков, ситуаций (включая разборы и лучший вариант), тестов и заданий лежит в HTML.
- Без JS: все этапы раскрыты, все четыре шага показаны подряд, разбор ситуации — в `<details>` «Показать разбор», поле дневника и отметки скрыты пояснением «нужен JavaScript». С JS разметка превращается во вкладки и сворачиваемые этапы.

## Доступность

- Этапы — нативные `<details>/<summary>`. Шаги этапа — вкладки (`role="tablist"`, `tab`, `tabpanel`, стрелки влево/вправо, `aria-selected`). Варианты ситуации — кнопки с `aria-pressed`; разбор появляется в области `aria-live="polite"`. Отметки — нативные чекбоксы с доступным именем, включающим название урока/задания. Поле дневника с `<label>`, счётчик связан через `aria-describedby`.
- Видимый фокус у всех элементов; состояния передаются текстом и значками, не только цветом.

## Затронутые файлы

- `academy-content.js` — 20 ситуаций.
- `tools/academy-render.js` — новая разметка страниц и валидация ситуаций; справочник ID для браузера дополняется ситуациями и заданиями.
- `js/academy.js` — хранение v2 с переносом, шаги, ситуации, практика, дневник, вкладки, сворачивание, следующий шаг, панель «Продолжить».
- `css/academy.css` — новая раскладка по макету.
- `build-pages.js` — только тексты description (число уроков из данных вместо вписанного руками).
- Сгенерированные `academy/**`, `deploy/academy/**` — пересборкой `node build-pages.js`. Остальные страницы, меню и `theme-dark.css` не меняются.

## Вне объёма

Карточки терминов, итоговый экзамен, достижения и серии дней, экспорт дневника, синхронизация между устройствами, отдельные страницы этапов, новые адреса, изменения меню и других разделов сайта.

## Проверка

- Сборка: `node build-pages.js` проходит; намеренно сломанная ситуация (несуществующий гайд, 2 варианта) останавливает сборку понятной ошибкой.
- Сценарии в браузере (Playwright, скрипт вне репозитория — как в MVP, по решению плана не добавлять набор тестов):
  - перенос v1 → v2 сохраняет отметки и результаты;
  - ситуация: выбор, разбор, смена выбора, счётчик этапа;
  - тест и практика двигают «Следующий шаг» в правильном порядке; этап получает «Завершён»;
  - дневник: сохранение, ограничение 500 символов, удаление, текст `<script>` выводится как текст, предел 30 записей;
  - сброс одного маршрута не трогает другой; две вкладки не затирают друг друга;
  - повреждённое и недоступное хранилище — без ошибок JS;
  - вкладки и сворачивание с клавиатуры; без JS всё содержимое видно;
  - ширины 360 / 390 / 768 / 1280 без горизонтальной прокрутки, с загруженными шрифтами Google; скриншоты для владельца.
- Ревью ветки отдельным агентом перед обновлением PR.
