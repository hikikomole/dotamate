## Этап 1. Резервная копия и эталон (до любых изменений)

**Что сохранить**
- Код сервера: `~/dotamate-src` без `data/` и без секретов (`--exclude=.env --exclude=secrets --exclude='*.txt'` у корня — `stratz.capi.txt`, `telegram.txt`, `github.pat.txt`, `Steam.txt`).
- Webroot: `~/www/dotamate.ru` целиком — уже есть `~/www/dotamate.ru.old` после выкладки, но он перезаписывается следующей выкладкой; нужна отдельная копия.
- Расписание: `~/dotamate-collector/crontab.txt` + вывод `crontab -l`, `skip-if-daily.sh`.
- Итоговые данные: `data/*.json`, `data/builds/`, `data/meta-match/`, `data/stats-history-steam/`, `data/steam-matches/_state.json`, `data/meta-matches/_tried.json`.
- Сырые базы (`steam-matches` ≈1,4 ГБ, `public-matches*`, `meta-matches`) — **не копировать**: они восстанавливаются сбором и не меняются планом. Копировать только если этап затрагивает их запись (этапы 2–3 не затрагивают).
- `~/dotamate-data/pro`, `feedback.sqlite` — не затрагиваются; копию не делать.

**Где**: `~/backup/2026-10-XX-stats/` на сервере — вне webroot и вне `~/dotamate-src`; дополнительно скачать архив на компьютер в `Claude outputs/backup/` (не в git: `Claude outputs` не в репозитории — проверить `.gitignore` перед этим). Секреты в архив не попадают; их копия — отдельная задача владельца, не в этом плане.

**Целостность**: `sha256sum` по каждому файлу → `MANIFEST.sha256` рядом с архивом; после скачивания — сверка на компьютере.

**Проверка восстановления вне production**: распаковать архив в облачный стенд, поднять статику webroot + `index.php` локальным PHP (или статикой + заглушками, как в claude/start-novogo-chata.md «Проверка»), открыть /stats/, /hero/<slug>/ в Playwright, сравнить скриншоты с живым сайтом.

**Эталон расчётов** (`baseline/`): копия `stats.json`, `our-meta.json`, `our-matrix.json`, `hero-counters.json`, `hero-main-roles.json`, `item-stats.json`, `hero-items.json`; плюс скрипт сравнения `tools/compare-stats.js` (новый, служебный, не на сайт) — сравнивает два набора файлов по полям: число матчей, wr/lo/pr/tier каждого героя, synergy/counters, позиции, предметы, линии; печатает расхождения сверх 0,05 п.п. На этапе 1 он только создаётся и прогоняется «эталон vs эталон» (0 расхождений).

Важно: сборщики на сервере пересчитывают данные каждый день, поэтому «до/после» сравнивать **на одном и том же снимке сырых данных**: на стенде прогнать старый и новый код по одной копии базы (для Steam — 1–2 дневных файла, чтобы уложиться в память стенда).

**Удаление копии**: только отдельной командой владельца, не раньше чем через 7 дней после последней выкладки по плану без откатов и при двух успешных ежедневных обновлениях подряд. Удаляется `~/backup/2026-10-XX-stats/`; локальная копия — по решению владельца.

**Приёмка**: архивы и манифест есть, сверка sha256 прошла, восстановленная копия открывается на стенде.

## Этап 2. Фоновое обновление: надёжность без смены формул

Плюс в `daily-update.js` перед `sync-deploy` — проверка, что ключевые `data/*.json` парсятся (`JSON.parse`), иначе выкладка отменяется.
3. **Затрагивает**: только способ записи; форматы, формулы, страницы — нет.
4. **Проверка без prod**: на стенде прогнать сборщики, `compare-stats.js` с эталоном → 0 расхождений; искусственно убить процесс в середине записи (`kill -9`) → старый файл цел.

6. **Побочные эффекты**: остающиеся `*.tmp` при сбое — `sync-deploy` их скопирует в deploy. Добавить `.tmp` в исключения `sync-deploy.js` в том же шаге; заметно по `ls deploy/data/*.tmp`.
