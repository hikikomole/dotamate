# Локальный PoC получения replay salt

PoC проверяет только запрос `match details` к Dota Game Coordinator и получение replay salt. Реплеи не скачиваются и парсер не запускается.

Ключ Steam Web API — отдельная вещь: он нужен сборщику публичных матчей через Valve Web API, но не даёт доступ к Dota Game Coordinator и не заменяет Steam-логин.

Чтобы сохранить ключ локально, создай `secrets/steam-api-key.txt` рядом с `Steam.txt` и помести в него только сам ключ одной строкой. Пример формата — `secrets/steam-api-key.txt.example`. Настоящий файл игнорируется Git.

## Подготовка

1. Установить зависимости проекта: `npm install` (npm registry должен быть доступен).
2. Хранить отдельный Steam-аккаунт локально в `secrets/Steam.txt`: логин первой строкой, пароль второй. Файл и состояние Steam-сессии исключены из Git и архива отправки на сервер.
3. Запустить с одним или несколькими известными ID матчей (не более пяти). Используйте ID публичных матчей, для которых Valve ещё хранит реплей:

   ```powershell
   node tools/replay-poc.js --match 1234567890
   ```

Steam Guard сейчас не запрашивается интерактивно: при его появлении скрипт безопасно завершится. Не помещайте пароль в аргументы командной строки или переменные репозитория.

## Результат

Успешная строка сообщает, что salt получен, и показывает cluster, но не выводит сам salt. Replay URL сохраняется локально в `secrets/replays/<match_id>.json`. Для скачивания одного реплея используйте `npm run replay:download-poc -- <match_id>`. Скрипт допускает только Valve replay-хосты, ограничивает размер 512 МБ и время 120 секунд, определяет bzip2 или Zstandard по сигнатуре и сохраняет фактическое расширение. Для Zstandard-файла распаковка: `npm run replay:decompress-poc -- <match_id>`; поток ограничен 2 ГБ и проверяется заголовок `PBDE`.

## Технические ограничения

- Включён WebSocket режим Steam (`webCompatibilityMode`) для сетей, где доступен порт 443.
- Максимум пять матчей за запуск и один общий таймаут 20 секунд; лимиты Valve и Steam могут меняться.
- Версия Dota GC communicator зафиксирована на опубликованной версии 1.1.4 (апрель 2025); пакет возвращает match details и replay URL, но совместимость его protobuf с текущим GC надо подтвердить реальным ответом.
- Парсер Clarity ещё не подключён. Для него потребуется Java 17 или новее.
- Загруженные replay-файлы и URL не попадают в Git; локально удаляйте их после проверки.

## Первый локальный прогон

Матч `9017989603` успешно прошёл цепочку GC → replay download → Zstandard decompression. Valve вернула cluster `182`; адрес файла оканчивался на `.dem.bz2`, но содержимое имело Zstandard magic `28 b5 2f fd`. После распаковки заголовок демо `PBDE` подтвердился.

Полный результат независимого проверочного парсера Gem сохранён локально в `secrets/replays/9017989603.parsed.json` (около 89 МБ). В матче распознаны 10 игроков, по 1 735 записей `[tick, x, y]` на игрока, 73 467 combat-log записей, 52 ward-события, 27 objectives, 21 teamfight и 28 минутных точек gold/XP advantage. Используй JSON как локальный fixture для построения формата расширенной статистики; это подтверждает доступность данных на одном матче, но ещё не означает, что Gem станет основным production-парсером.

Чтобы собрать локальный интерактивный отчёт позиционной статистики по разобранному матчу:

```powershell
npm run replay:position-report -- 9017989603
```

Команда создаёт локальный архив в `match-archive/`: индекс матчей `index.html`, страницу повтора `matches/<match_id>.html`, нормализованный компактный JSON `matches/<match_id>.json` и индекс-данные `index.json`. Страница показывает движение по координатным sample-точкам, временные события, выбранные минутные срезы экономики/опыта/урона, преимущество Radiant и итоговую статистику игроков. Позиция при смерти приблизительная; минутные значения доступны только в sample-точках, непрерывной интерполяции нет. В страницы не включаются игровые имена и Steam ID.

Локальный просмотр: запусти сайт `npm start`, затем открой `/match-archive/`. Нормализованный архив и страницы строятся заново командой выше. Каталог `match-archive/` игнорируется Git, так как содержит производные локальные данные матча.

Ограничение: текущий полный JSON создан проверочным парсером Gem. Это не подтверждает ещё совместимость схемы и качество парсинга на произвольных матчах или будущих версиях Dota 2.
