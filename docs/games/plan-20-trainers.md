# 20 браузерных тренажёров DotaMate

Механики в `js/games/data/mechanics.json` извлечены локально из `game/dota/pak01_dir.vpk` (NPC KeyValues) и `game/dota/steam.inf`; версия клиента указана в заголовке JSON.

Статус: только дизайн. Цель — один реальный навык за короткую сессию, немедленное объяснение ошибки и повтор. Ровно 20 новых игр плюс существующая Hook & Hit: 21 карточка хаба. Подготовлено без сети; поисковая частотность не измерялась.

## Основания и источники

Изучены CLAUDE.md, game/index.html, js/game.js, page-shell.html, tools/site-nav.js, build-pages.js, docs/architecture/data-independence.md и локальные данные. Hook & Hit — IIFE, Canvas 800×600, pointer input, Classic/Endless, рекорды dgBest.v1, пауза через IntersectionObserver. Она совмещает добивания, уклонение и отражение; это legacy-исключение из правила одного навыка, а не тренажёр броска хука.

Отдельных data/timings.json и data/item-counters.json в текущем списке нет. Точные stack/pull timings, attack point и скорости снарядов не подставлять из памяти. Файлы локального клиента могут стать источником только после проверки наличия, версии и конкретного ключа; сейчас их наличие не предполагается.

Каждый реальный факт сопровождается provenance {file,key,field,version,excerpt}. При сборке редакционно выделять небольшой проверенный пул, не извлекать смысл/числа из текста regex на клиенте. Пропуски и противоречия исключают задачу; нехватка задач блокирует публикацию игры. Молчание описания не доказывает отсутствие свойства. Не смешивать Ranked/Turbo, даты и разные снимки. Runtime использует только локальную статику, без /api/dota, Stratz, OpenDota и Valve.

## Общие правила

Все 20: обучение без очков → 120 секунд активного времени → результат, повтор и хаб. Три уровня: новичок/обычный/сложный. После ошибки — причина, визуальный разбор и повтор похожего эпизода. Результат: очки, точность, профиль ошибок, личный рекорд; минимум очков 0. Скорость не компенсирует неправильный ответ. Рекорды разделены по id, difficulty, rulesVersion, dataVersion; seed позволяет повторить ситуацию, случайные сессии не объявляются равными по сложности.

Все очки, бюджеты задач и учебные скорости — параметры тренажёра. Для условных моделей до старта и в HUD: «Условная модель: значения отличаются от Dota 2». Это тренировка принципа, не точных значений конкретного героя. Только оригинальные CSS/SVG/Canvas-фигуры, буквы, линии; никаких Valve art, логотипов, портретов, иконок и трассировки карты. Поля img не использовать. Названия героев/предметов допустимы текстом.

## Приоритет и партии

Порядок — экспертная оценка сочетания заданных поисковых намерений, тренировочной ценности и стоимости, без заявлений об измеренном спросе. S — простой экран/правило; M — несколько состояний/динамика; L — взаимодействующая модель. Стоимость движка отдельно.

1. Партия 1, №1–5: hook-aim, last-hit, deny, item-recipes, stun-chain — хук/ластхит и переиспользуемая основа таймингов.
2. Партия 2, №6–10: counter-pick, budget-build, minimap-awareness, rune-timing, cooldown-tracking.
3. Партия 3, №11–15: mana-management, combo-order, blink-dodge, spell-immunity, dispel-choice.
4. Партия 4, №16–20: gold-efficiency, roshan-window, stack-timing, creep-aggro, lane-equilibrium — дорогие модели линии последними.

### 01. hook-aim — «Точный хук»

- Рост/счёт: прямая → повороты → препятствия; +100 попадание, −20 промах; точность отдельно.
- Источник: условная геометрия файла игры; имя Meat Hook — hero-abilities.json, Pudge, pudge_meat_hook; скорость/дальность не реальные.
- Управление: мышь+клик/Q, стрелки прицела; touch — drag прицела и кнопка броска.
- SEO title/H1: «Симулятор хука Дота — тренировка прицела | Dota Mate» / «Симулятор хука Дота»; description: «Тренируйте упреждение на движущихся целях. Две минуты, условная модель и личный рекорд.»

## Общий движок: API (18 строк)

```text
createTrainer({id,root,canvas?,duration:120,difficulty,rulesVersion,dataVersion,seed}) -> engine
engine.mount({setup,update,render,onAction,dispose}) — интерфейс отдельной игры.
setup(ctx) -> state; конкретные правила/коллизии остаются в игре.
update(state,dt,ctx); render(state,view,ctx); DOM-игре canvas не обязателен.
onAction(state,{name,phase,x?,y?},ctx) — одинаковые действия для всех устройств.
ctx.clock — активное время; RAF, ограниченный dt, фиксированный шаг для таймингов.
ctx.rng — seeded random для повторения эпизода.
ctx.input.bind(actions) — Pointer Events, capture/cancel, логические координаты.
ctx.input.bindKeys(map) — только в фокусе игры, без захвата клавиш страницы.
ctx.view — ResizeObserver, logical size, DPR с пределом; CSS/backing sizes раздельно.
ctx.motion.reduced — убрать частицы/вспышки, сохранить телеграфы и время реакции.
ctx.feedback({kind,message,detail}) — разбор и умеренное aria-live.
ctx.score.add(delta,reason); ctx.finish(metrics) — единственная финализация попытки.
engine.start/pause/resume/destroy — освобождение RAF/обработчиков.
visibilitychange/blur — пауза, сброс input; ручной resume, без скачка dt.
best.load/save — try/catch JSON+localStorage, валидация схемы, fallback в память.
results — score,accuracy,errorProfile,best,retry,hub; доступные кнопки и фокус.
analytics — ym(112755250,'reachGoal','game_start'|'game_finish',{game_id:id,difficulty,score?}).
```

Ключ рекорда включает id/уровень/версии; старый рекорд виден на результате. pointercancel сбрасывает зажатые действия. Счётчик — из page-shell.html; вызывать в try/catch только после существующего analytics-consent и при typeof ym === 'function'. Один start при начале отсчёта, один finish по таймеру/явному завершению; пауза и закрытие не finish. Без ym игра работает. Никаких новых внешних тегов, личности или пользовательского ввода в событиях. В этой задаче события не отправляются. Legacy не подключать к движку ради унификации.

## Риски и будущая приёмка

1. Локальные факты могут устареть или противоречить друг другу; дата сборки не доказывает актуальность патча. Проверять согласованность локальных источников и маркировать версии. BKB/dispel могут не набрать достаточного пула явно подтверждённых пар — блокер публикации, не повод выдумывать ответы.
2. Условные attack point, Invoker-style, агро/равновесие не обучают точным значениям героя; подпись модели постоянно видна. L-модели линии — главный риск стоимости и неверного переноса навыка.
3. Статистика контрпиков требует minGames, даты и режима; не смешивать корреляцию/эффект, итоговый инвентарь/реальные тайминги. Обновления внешних сервисов не должны быть обязательны для работы.
4. /game/ имеет поисковый трафик. Перед/после будущей сборки сравнить legacy-вывод и проверить оба режима, restart, pointer, рекорды. Сейчас builder не запускать: он меняет множество страниц и data/live-items.json.
5. Проверить DPR/resize/rotation, touch cancel, portrait/landscape, keyboard focus, reduced-motion, hidden→resume без хода времени, отсутствие scroll lock вне поля. Корректность таймингов не должна зависеть от частоты кадров.
6. Заблокированные storage/ym и повреждённый JSON не ломают игру. Нет фактов — старт блокируется с объяснением, без вымышленных задач. Аналитика только с consent, по одному game_start/game_finish с game_id.
7. На каждую игру: успешный/ошибочный эпизод, объяснение, рост сложности, формула очков, 120 активных секунд, личный рекорд по уровню/версии, повтор. Проверить локально с заблокированной внешней сетью; внешнюю рекламу/аналитику общего shell учитывать отдельно.
8. Сборочная приёмка: 20 уникальных новых slug, 4 партии по 5, 21 карточка с legacy, уникальные title/description/H1/canonical, рабочие ссылки, provenance каждого факта. Это будущие проверки реализации, не утверждение о работающих играх.
