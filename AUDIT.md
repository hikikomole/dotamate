Полная проверка счётчиков, перекрёстных ссылок и источников данных (герои/предметы/статистика/описания).
Что можно было исправить сразу — исправлено и закоммичено. Остальное — конкретный план с оценкой сложности.

## 1. Счётчики на главной — все верны, но зависят от источника данных

`heroCount`, `quickHeroCount`, `itemCountHero`, `quickItemCount`, `itemCountHero2`, `itemVisibleCount` — все
считаются как `array.length` от реально загруженных данных (`js/app.js`, функции `updateHeroUI`,
`updateItemCounters`, `renderItems`). Логика верна: `itemVisibleCount` — это отфильтрованные предметы
(поиск/категория), `itemCountHero`/`quickItemCount` — общее число в базе. Не спутаны местами, это разные,
корректно используемые счётчики.

`heroRoleCount` — количество уникальных ролей (`new Set(heroes.flatMap(h=>h.roles||[]))`) — верно, с fallback
на «—», если ролей нет.

`bestWinrate` / `proPicks` — зависят от поля `pro_pick`/`pro_win`, которого нет в «аварийном» локальном
списке героев (`js/local-preview.js`). Это не баг, а ожидаемое поведение резервного режима (см. п.3).

**Вывод:** сама логика счётчиков корректна. Единственный риск — откуда фактически приходят данные, это
разобрано ниже.

## 2. Откуда берутся герои/предметы/статистика — работает, но не одинаково в проде и в превью

Проверено вживую (реальные сетевые запросы, не догадки):

- **Локальный превью-сервер (`preview-server.js`)** — правильно и по порядку опрашивает Valve datafeed →
  OpenDota → dotaconstants (GitHub), сливает результаты (`mergeHeroStats`/`mergeItems`), кэширует на диск
  (`.d2h-data-cache-v43/`). Я запустил его и получил реальные данные: 100+ героев с ролями/статами и
  предметы с официальными описаниями способностей на английском (Valve отдаёт `abilities[].description`).
  Это тот код, который сейчас реально работает у вас локально.

- **Продакшн-сервер (`server.js`, функция `dotaProxy`)** — реализован **гораздо беднее**: опрашивает
  **только OpenDota**, без Valve datafeed и без dotaconstants, без слияния и без дискового кэша (только
  HTTP-заголовок `Cache-Control: max-age=300`). Это значит, что после реального деплоя счётчики и списки
  героев/предметов будут работать (OpenDota один справляется), но:

  - **эндпоинт `/api/dota/item/:id`** (детальное официальное описание одного предмета) **отсутствует в
    `server.js` вообще** — он есть только в `preview-server.js`;
  - **эндпоинт `/api/dota/hero/:id/items`** (реальная статистика покупок предметов под героя,
    `loadHeroItemPopularity` в `app.js`) — тоже отсутствует в `server.js`.

  Фронтенд (`js/app.js`) обращается именно к этим путям. Без них при попытке достучаться он попробует
  дёрнуть `https://www.dota2.com/datafeed/...` прямо из браузера — и это, скорее всего, упрётся в CORS
  (сторонний домен без разрешающих заголовков для чужого сайта). Итог: в текущем виде после деплоя карточка
  предмета будет вечно показывать «Официальное описание загружается…», а блок «реальные покупки предметов»
  в профиле героя — не загрузится.

  **Решение:** перенести логику `getItem`/`getHeroItems` и роуты `/api/dota/item/:id`,
  `/api/dota/hero/:id/items` из `preview-server.js` в `server.js` (код уже написан и проверен — это
  перенос, а не разработка с нуля). Это правка `server.js`, поэтому по правилам из `CLAUDE.md` я не стал
  вносить её без вашего подтверждения — готов сделать в следующий шаг.

## 3. Описания героев — ключевая находка: способности сейчас ПОДДЕЛЬНЫЕ

Открыл карточку героя (функция `openHero` в `js/app.js`). Блок «Способности» показывает для **любого**
героя одни и те же четыре подписи-заглушки:

```
Основная способность / Контроль / прокаст / Усиление героя / Ультимейт
```

с текстом «Подробное описание и значения загружаются из актуального Dota 2 datafeed в онлайн-режиме» —
но по факту **ничего никуда не грузится**, это статичный шаблон, одинаковый для всех 124 героев. Реальных
названий и описаний способностей на сайте сейчас нет вообще.

**Где взять реальные данные (проверено):**

- `https://api.opendota.com/api/constants/hero_abilities` — список внутренних ключей способностей по
  каждому герою (например, `antimage_blink`, `antimage_mana_break`…).
- `https://api.opendota.com/api/constants/abilities` — описания способностей по этим ключам (название,
  тип, урон, значения по уровням). Это стандартный источник, которым пользуется вся экосистема OpenDota/
  Dotabuff — бесплатный, без ключа API.
- Текст в этом источнике **на английском**. Официального бесплатного API с русскими текстами способностей
  я не нашёл: проверил параметр `?language=russian` и `?language=ru` у Valve datafeed — первый молча
  возвращает английский текст, второй отвечает ошибкой (`{"result":{"status":8}}`). То есть локализация
  через сам Valve datafeed ненадёжна, полагаться на неё нельзя.

**Что предлагаю (на выбор, не решаю за вас):**
1. Подключить `hero_abilities` + `abilities` с английским текстом — быстро, бесплатно, честно (реальные
   данные вместо заглушки), но не на русском.
2. То же самое + машинный перевод через API (например Yandex.Translate/DeepL) с кэшированием перевода на
   сервере — небольшая абонентская стоимость перевода, но сайт станет русскоязычным по-настоящему.
3. Вручную написать короткие RU-описания способностей для самых популярных ~20–30 героев (по данным
   «Меты» на сайте) как контент высокого качества, остальных — покрыть вариантом 1. Дольше, но не требует
   платного API и текст будет живым, а не переводным.

## 4. Описания предметов — инфраструктура уже написана и рабочая, два открытых вопроса

В отличие от героев, для предметов на сайте **уже есть настоящий, работающий (в превью) механизм**:
`openItem()` тянет официальные данные Valve (`desc_loc`/`description`, `cooldowns`, `mana_costs`,
`cast_ranges`, `special_values`) через кэш в `localStorage` и подпись «Источник текста: Valve Datafeed».
Я открыл его вживую — предметы вроде Blink Dagger реально получают официальный английский текст
способности. Это хорошо спроектированная часть сайта.

Два реальных ограничения:
1. Как в п.2 — в продакшне (`server.js`) нет эндпоинта `/api/dota/item/:id`, поэтому в реальном деплое
   этот механизм скорее всего не будет получать данные без переноса кода из `preview-server.js`.
2. Текст на английском по тем же причинам, что и у героев (см. п.3) — то же решение (перевод/кэш/вручную)
   применимо и здесь.

## 5. Перекрёстные ссылки — было расхождение, сейчас исправлено

Проверил все `<nav>`, `href="#..."`, `data-go`, элементы глобального поиска (Ctrl+K) во всех HTML/JS
файлах. Нашёл и исправил:

- **Расхождение навигации.** У `index.html` в шапке был пункт «Мета», но не было «О сайте»; у пяти

  индексировались глобальным поиском (Ctrl+K). Добавил их (и «О сайте») в индекс поиска

Всё проверено локально (все страницы отдают 200, JS без синтаксических ошибок) и закоммичено.

не перегружать шапку девятью-двенадцатью пунктами) — сейчас они доступны через прокрутку и через поиск.
