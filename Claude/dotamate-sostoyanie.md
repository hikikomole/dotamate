### Делегирование: как это было сделано

Тексты писала Gemini (`tools/llm.py -p gemini`) по факт-листам, которые собрал
Claude: в факт-листе заранее перечислены заголовки разделов и все допустимые
числа. Два прохода — первый пишет разделы, второй добавляет в каждый раздел по
одному практическому абзацу. Числа, формулы, таблицы, правка и сверка — Claude.

**Проверка скриптом обязательна и окупилась:** `check2.js` сверяет каждое число
из текста со списком разрешённых, проверяет, что заголовки на месте, что абзацы
первого прохода не переписаны, что нет коротких абзацев и дублей между статьями.
Замечания, которые поймал скрипт и ручная вычитка: ollama лежал (`--check` показал
сразу), Gemini дважды обрывала JSON на последних скобках (чинится дописыванием
`]}`), один раз дописала мусор после закрывающей скобки, придумала «баночные
параметры» и совет «смотреть статистику входящего урона во время сражения»
(такого в игре нет). Числа при этом не выдумала ни разу — потому что их
диапазон был задан жёстко.

## Сессия до этого: инструмент драфта на главной

Секция `#draftTool` между первым экраном и блоком «Что есть на сайте».
Аналог D2PT Draft Tool: два состава по пять слотов, баны, быстрый ввод с подсказками,
автоматическая расстановка позиций, рекомендации по обеим сторонам, перевес драфта
и перевес на линиях, ссылка на драфт через хеш, отмена и сброс.

Файлы: `js/draft-tool.js`, `css/draft-tool.css`, разметка в `page-sections.html`,
сборщики `fetch-draft-matrix.js` и `fetch-lane-matrix.js`,
проверки `tools/check-draft-matrix.js` и `tools/check-lane-matrix.js`.

### Откуда данные

- `data/draft-matrix.json` — Stratz `heroStats.matchUp`, бракет DIVINE_IMMORTAL.
  **Stratz отдаёт пару несимметрично**: у каждого героя своё окно выборки, поэтому
  доля побед сведена как взвешенная средняя двух направлений, а matchCount — большее из двух.
- `data/lane-matrix.json` — Stratz `heroStats.laneOutcome`, фактические исходы линий.

### Ограничение Stratz, которое всё определило

**Токен Stratz работает не более чем с двух IP-адресов за 15 минут.** Cloudflare Worker
ходит наружу с разных адресов, поэтому живые запросы к Stratz из воркера отдают 403.
Оба среза собираются скриптами с одной машины и выкатываются статикой.

### Как считается

Доля побед пары сглаживается к 50% по выборке: `(победы + 25) / (матчи + 50)`, K = 50.
Отклонения складываются в процентных пунктах. Линии усредняются по обоим встречным
срезам Stratz, иначе зеркальный драфт давал разный ответ.

## Рабочие приёмы

- Токен GitHub — в `github.pat.txt` (`github.pat=<токен>`), токен Stratz — в `stratz.capi.txt`,
  токен Cloudflare — в `.env` (`CLOUDFLARE_API_TOKEN`).
- **Пуш без утечки токена.** Remote остаётся чистым `https://github.com/hikikomole/dotamate.git`,
  токен подаётся через временный `GIT_ASKPASS`-скрипт в `$HOME` Linux-VM, который удаляется
  сразу после пуша. Вывод прогоняется через `sed` с заменой `ghp_*` и `//user:token@`.
- **Удаление файлов в папке проекта по умолчанию запрещено** — git оставляет
  `.git/HEAD.lock` и `.git/index.lock` и спотыкается на следующей команде. Лечится
  запросом `device_request_delete_permission` на папку проекта (до конца сессии),
  после чего `rm -f .git/*.lock`.
- Деплой: `node tools/sync-deploy.js`, затем из `deploy/`:
  `set -a && . ../.env && set +a && npx wrangler deploy`.
- `node build-pages.js` безопасен: главная собирается вместе с инструментом драфта.
- `tools/sync-deploy.js` синхронизирует только `css`, `js`, `assets`, `data` и мелочь
  в корне. Страницы разделов даёт `build-pages.js`, страницы гайдов — `build-guide-pages.js`.
- **Фоновые процессы в device_bash не выживают между вызовами** (`nohup ... &` умирает).
  Длинные запросы к внешним моделям гонять по одному на вызов, укладываясь в лимит.
- Правки проверять скриптом на живом сайте, а не на глаз.
