# Оценка MMR игрока — разбор и план (03.10.2026, НЕ утверждено, код не менялся)

## Как сейчас
- Личной оценки MMR на сайте нет. /me (js/me.js) ранг не показывает.
- «0–4500 MMR» — подпись среза базы: tools/collect-public-matches.js берёт матчи OpenDota /publicMatches с avg_rank_tier 10–65 (Herald 1…Ancient 5). Это средний ранг матча, не игрока. По нашей же таблице Ancient 5 = 4466–4620, т.е. честнее «до ~4600».
- Таблица звёзд в гайде ranks-mmr (guide-content.js): шаг 154 MMR, Divine 200, по Dota 2 Wiki, приблизительно.

## OpenDota (проверено по коду odota/core, коммит 02.10.2026, и API)
- /players/{id}: rank_tier (медаль*10+звезда, из профиля GC), leaderboard_rank (Титаны), computed_mmr, computed_mmr_turbo.
- computed_mmr (svc/rater.ts): Эло, старт 4000, K=50, ожидание по среднему рейтингу команд, все в команде получают одинаковую дельту. Считаются только ranked-матчи с match_id%100 < RATING_PERCENT (выборка) и где все 10 account_id известны. Это НЕ MMR Valve.
- /players/{id}/matches: поле average_rank у матча (часто null).
- CORS: Access-Control-Allow-Origin: https://dotamate.ru — браузер посетителя может звать OpenDota сам (лимит на IP посетителя).

## Предложенная модель (диапазон, не число)
1. rank_tier есть → диапазон звезды по таблице (напр. Legend 3 = 3388–3541). Титан → «Титан, место N», без MMR.
2. rank_tier нет → медиана average_rank по последним ≥10 ranked-матчам → диапазон медали, уверенность «низкая/средняя» по числу матчей и разбросу.
3. Данных нет → «ранг скрыт», без числа.
4. computed_mmr — не показывать как MMR (иная шкала).
Проверка: выборка игроков с известным rank_tier, считать п.2 вслепую, доля попаданий в ±1 медаль, ошибка в звёздах.
