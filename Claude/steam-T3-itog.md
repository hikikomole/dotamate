- Эталон: сервер ~/dotamate-src/data/meta-matches (Stratz, 23.09–03.10): 9 066 уникальных матчей, из них 894 без полной расстановки 1–5 в обеих командах отброшены → 8 172 матча (81 720 игроков).
- Steam-данные по match_seq_num для всех 8 172 не скачивались: пересечение с уже собранной T1/T2 базой data/steam-matches (02.10) — 102 матча; на них поля Stratz h, порядок слотов, gpm, xpm, lvl, net_worth, итоговые 6 предметов совпали со Steam у 1020 из 1020 игроков. Поэтому обучение и оценка — на этих полях Stratz как точной копии Steam. Отдельно проверено на 85 матчах (после отбраковки), где признаки собраны ТОЛЬКО из Steam-строки (расхождений полей 0).
- Признаки (всё есть в Steam): для gpm, xpm, nw, lh, denies, hero_damage, tower_damage, healing, K, D, A, level — ранг внутри команды и доля от суммы команды; итоговые предметы (196 id, встречающихся ≥30 раз в train); слот 0–4; априорное распределение позиций героя (только из train, для строк train — leave-one-out, без утечки своей метки). Не используются: pos, линии, время покупок, account_id.
- Деление по матчам: sha256("t3-2026-10-03:"+match_id) → 70/15/15: train 5 713, val 1 245, test 1 214 матчей. Игроки одного матча всегда в одной части.
- Модель: softmax-регрессия на чистом Node (SGD, L2), параметры выбраны на val (l2 1e-5, 16 эпох), затем назначение позиций в команде перебором 120 перестановок (каждая позиция ровно один раз).

## Порог
- Общий порог 85 % НЕ достигнут (79,46 %) — из-за 4↔5.
- Предлагаю порог по назначению, а не один: кор/саппорт ≥ 95 % (есть 96,92 %); позиции 1, 2, 3 — каждая ≥ 85 % (есть 87,9–91,8 %); 4 и 5 по отдельности ≥ 85 % (нет: 62,9 / 65,9 %). Обоснование: Stratz сам выводит позиции косвенно (эталон не абсолютен), а для сайта ошибка важна в агрегатах — при 85 %+ по позиции искажение распределения героя по ролям держится в единицах п.п.; при 63–66 % для 4/5 сборки «поз.4» и «поз.5» будут смешаны.
- Итог: Steam-оценка годится для кор/саппорт и для позиций 1, 2, 3; для раздельных 4 и 5 — нет.
