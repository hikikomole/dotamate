# ВЕРСИЯ САЙТА — ОБЯЗАТЕЛЬНО К ПРИМЕНЕНИЮ (решение владельца 02.10.2026)

**Этот документ — единственный источник номера текущей версии (см. «История» внизу). Номер также: curl -s https://dotamate.ru/api/version.**

Каждая выкладка на dotamate.ru получает номер версии, и **каждая новая выкладка = версия +1**. Это нужно, чтобы у всех посетителей сразу обновлялись скрипты, стили и данные: хостинг не отдаёт Cache-Control для js/css и кеширует статические JSON, без версии браузер держит старый скрипт при новой странице (так 02.10 «не работала» кнопка «Divine 5 и Immortal» и были старые квадраты строений на /live).

**Решение владельца 10.10.2026:** версия — ещё и журнал изменений. Каждая выкладка, даже самая маленькая (одна правка CSS), получает +1 (это делает deploy-hostiman.js сам) **и обязательно запись в «История» этого файла в том же чате, сразу после выкладки.**

## Как устроено
- tools/deploy-hostiman.js: счётчик на сервере `~/dotamate-data/site-version.json` {version, deployedAt}, +1 при каждой успешной выкладке.
- Перед упаковкой во ВСЕ страницы deploy/ (кроме data/ и assets/) ко всем своим `/js/*.js`, `/css/*.css`, `/security.js` дописывается `?v=<версия>`, в `<head>` — `<meta name="dotamate-version" content="<версия>">`; в корень — `/version.json`.
- security.js (подключён на всех страницах первым): обёртка fetch дописывает `?v=<версия>` к запросам `/data/*` и `/version.json` — данные после выкладки тоже свежие.
- `/api/version` (deploy/api/index.php) — номер версии без кеша хостинга. Статический `/version.json` хостинг может отдавать старым несколько минут — для проверок использовать `/api/version`.
- Работает для страниц всех сборщиков. Ежедневное обновление (daily-update на сервере, 04:17 и 10:17 МСК) — тоже выкладка, тоже +1.
- **С U3 (выложен): ежедневное обновление выкладывает только данные.** deploy-hostiman.js после каждой успешной выкладки на сервере пишет отпечаток кода ~/dotamate-data/code-fingerprint.json (tools/code-fingerprint.js). daily-update.js сверяет код с ним в начале и перед sync: код изменён (push-server без «выкладывай») — данные пересчитываются, но выкладки нет, в logs/daily-*.log «ВЫКЛАДКА ЗАБЛОКИРОВАНА: …» со списком файлов, код выхода 2. Проверка вручную: `node tools/code-fingerprint.js --check`. Поэтому push-server без последующей выкладки останавливает ежедневную выкладку данных до ближайшей ручной выкладки. Это касается и серверных сборщиков в tools/ (например tools/replay/collect.js) — их правки тоже выкладываются по «выкладывай».
- С v86 (11.10.2026) при блокировке выкладки и фатальной ошибке daily-update пишет владельцу в личный Telegram (~/dotamate-data/telegram.env: TG_ALERT_CHAT; бэкап до правки — telegram.env.bak-alert).
- push-server только добавляет/обновляет файлы: удалённые на ПК файлы удалять на сервере (~/dotamate-src) отдельной командой в том же задании (так сделано в v71).
- Разборщик реплеев ~/dotamate-collector/dotamate-parser.jar push-server НЕ переносит (исключён) — ставить отдельно, с копией старого (так сделано в v72).

## Порядок выкладки (только так)
1. Правки на компьютере владельца, проверка.
2. Локально: `node tools/push-server.js` (код → ~/dotamate-src). secrets/ push-server НЕ переносит — отдельные файлы оттуда отправлять `node sshr.js "secrets\<файл>" "cat > ~/dotamate-src/secrets/<файл>"` (с бэкапом, без вывода содержимого).
3. На сервере: `cd ~/dotamate-src && export DOTAMATE_SERVER=1 && node build-pages.js && node tools/sync-deploy.js && node tools/deploy-hostiman.js` (если менялись страницы героев/предметов/гайдов/словаря/политики — перед sync их сборщики: build-hero-pages.js, build-hero-guides.js, build-item-pages.js, build-guide-pages.js, build-role-guides.js, build-glossary-page.js, build-privacy-page.js, затем build-sitemap.js). Для страниц предметов перед build-item-pages — tools/build-item-stats.js. Полная пересборка всех страниц занимает ~3–4 мин — в мосте ждать результат отдельным вызовом. **Шапка (tools/site-nav.js) меняется → нужны ВСЕ сборщики (шаблон s171.sh / s147.sh).**
4. Проверить: `curl -s https://dotamate.ru/api/version` — версия выросла на 1; в html `?v=<версия>`.
5. При заметных изменениях страниц — `node tools/indexnow.js` на сервере (без аргументов — весь sitemap, или список путей; Яндекс + api.indexnow.org; ключ 2c8e579f28eebdb6c463d02d501e3ed2.txt в корне сайта).
6. Запись в «История» этого файла (решение владельца 10.10.2026).
- Выкладка с рабочего компьютера запрещена: deploy-hostiman без DOTAMATE_SERVER=1 останавливается. Аварийный обход — `--from-pc`, только по прямому указанию владельца.
- В отчёте владельцу всегда писать номер выложенной версии.
- Выкладка — только после команды владельца.
- Номер версии перед выкладкой брать с сервера (site-version.json): между чатами бывают другие выкладки (02.10: ожидали 17, а 17 уже была — вышла 18).
- **В задании моста push и сборку на сервере связывать через `&&`** (push && sshr …), а не отдельными строками: 03.10 push упал по таймауту SSH, а сборка всё равно прошла на старом коде — лишняя версия v33.
- **Лимит процессов:** с 10.10.2026 тариф RuBig — 115 процессов, 3 ГБ (claude/limit-processov-hostinga.md). Длинную сборку на сервере по-прежнему запускать под `flock -w 900 ~/dotamate-collector/heavy.lock` (шаблоны ~/u5/deploy.sh, v7b.sh 09.10, dp1.sh 09.10, dp3.sh и dp4.sh 10.10), шаги строго по одному.
- После правки сборщиков, которые запускает cron, — смотреть ближайший запуск в журнале (10.10: --limit 6 сломал получение salt, откачено за 6 минут).
- Новую запись истории добавлять ТОЛЬКО в этот файл (раздел «История»), отдельных файлов истории не заводить.
- **10.10.2026: сборщик, который давно не запускался, оставляет на сайте старую шапку.** После добавления выпадающего «Эфира» (09.10) страницы /item/, /glossary/, /privacy/, /contact/ не пересобирались и шли без него; главная и разделы тоже выпали из меню (точная причина не установлена — корневой index.html на сервере был от 09.10 04:47). Проверка после выкладки: `grep -L nav-dd` по ~/www/dotamate.ru — должно быть пусто.

## Приёмы (02.10.2026)
- Задания моста `claude-shell.cmd` писать с концами строк CRLF (printf '%s\r\n'), иначе cmd рвёт строки. Кириллицу в командной строке не использовать — выносить в отдельный .js.
- Вывод задания моста перенаправлять в файл с ДРУГИМ именем, чем sNN.out (мост сам пишет sNN.out и затирает). В одной строке не ставить два перенаправления stdout — действует последнее (04.10 s954: вывод ушёл не в тот файл). Имена заданий не повторять: в out/ может лежать старый .out с тем же именем (10.10: w1.out от 09.10).
- Мост может быть не запущен или закрыться посреди работы (alive.txt не обновляется) — попросить владельца открыть "Claude outputs\claude-shell.cmd"; задание можно положить в shell\in заранее, мост заберёт его при запуске.
