# Dota 2 Companion (v43) — инструкция для Claude

Этот файл — «память» проекта. Открывай/учитывай его в начале любой сессии по этому сайту:
он экономит время на объяснение контекста заново.

## Что это за проект

Неофициальный сайт-помощник по Dota 2: герои, предметы, статистика, гайды, инструменты (калькулятор MMR,
рандом героя и т.п.) + встроенная стриминговая платформа (каналы, лайв через WebRTC/RTMP/HLS, чат, подписки,
донаты через CloudPayments). Фронтенд — статические HTML-страницы + vanilla JS, без фреймворка.

**Бизнес-цель:** сайт должен зарабатывать на контенте — реклама и партнёрские ссылки (гейминг-товары,
хостинг рефералки, донаты/CloudPayments уже реализованы). Это значит: SEO, скорость загрузки и удобство
чтения гайдов важны не меньше, чем новый функционал.

## Стек

- **Backend:** Node.js, без фреймворка — чистый `http` модуль (`server.js`, ~40к строк кода в одном файле).
  PostgreSQL (`pg`), Redis (`redis`), WebSocket (`ws`), JWT (`jsonwebtoken`), bcrypt (`bcryptjs`).
- **Frontend:** статический HTML + vanilla JS (`js/app.js`, `js/stream.js`, `js/studio.js`, `js/v43-*.js`) + CSS
  (`css/style.css` — большой основной файл, `css/stream.css`, `css/studio.css`, `css/v43-platform.css`).
- **Стриминг:** MediaMTX (WebRTC/WHIP/RTMP/HLS), Coturn (TURN для WebRTC ICE).
- **Инфраструктура:** Docker Compose (`docker-compose.yml`), Caddy как HTTPS reverse proxy (`Caddyfile`).
- **Данные о героях/предметах:** проксируются с dota2.com / OpenDota / dotaconstants (см. `js/app.js`,
  `dotaProxy` в `server.js`).

## Структура

```
index.html, auth.html, channel.html, profile.html, stream.html, studio.html  — страницы
css/       — стили (style.css — основной, остальные — под конкретные страницы)
js/        — клиентский JS (app.js — основная логика сайта, остальные — стриминг/студия)
assets/    — картинки
server.js  — весь backend: API, WebSocket, работа с БД, media-auth, security-заголовки
preview-server.js — лёгкий локальный сервер без БД/Redis, только для превью статики
security.js — клиентский security-хелпер, подключается на всех страницах
Caddyfile, docker-compose.yml, mediamtx.yml — продакшн-инфраструктура
```

Git-репозитория в проекте пока нет. Прежде чем делать масштабные правки, стоит завести `git init` —
это позволит откатывать неудачные изменения (спроси/предложи, если будем это делать).

## Карта данных — какой файл за что отвечает (prod vs preview)

Это осознанно два РАЗНЫХ по возможностям сервера, и они расходятся по-настоящему — вот что именно
куда ходит, чтобы это не пришлось каждый раз заново разбирать:

- **`preview-server.js`** (локальный запуск, `Open Dota 2 Helper.cmd`) — самый полный источник:
  - Список героев/предметов: опрашивает по очереди Valve datafeed → OpenDota → dotaconstants (GitHub),
    берёт первый успешный как основу и досливает поля из остальных (`refreshHeroes`/`refreshItems`,
    `mergeHeroStats`/`mergeItems`). Кэширует результат на диск (`.d2h-data-cache-v43/`).
  - Детали предмета (`/api/dota/item/:id`) и способности героя (`/api/dota/hero/:name/abilities`) —
    тянет с Valve datafeed / OpenDota `constants/hero_abilities`+`constants/abilities`, переводит через
    `translateToRu()` (DeepL, кэш на диске).
- **`server.js`** (прод, `dotaProxy` для `/api/dota/heroes` и `/api/dota/items`) — использует Redis-кэш
  вместо дискового (не диск, как в preview), и не полностью 1-в-1 с preview:
  - `/api/dota/heroes` — опрашивает **только OpenDota** (без Valve/dotaconstants), но этого достаточно:
    OpenDota `heroStats` уже содержит всё нужное поле `name`, багов не было.
  - `/api/dota/items`, `/api/dota/item/:id`, `/api/dota/hero/:id/items`, `/api/dota/hero/:name/abilities` —
    все **перенесены/дополнены** до того же уровня, что и `preview-server.js` (см. «Технические долги»
    ниже), включая то же слияние Valve → OpenDota → dotaconstants для списка предметов.
- **`js/app.js`** (клиент) — своя копия `normalizeHeroes`/`normalizeItems`, логически зеркалит то, что
  делает `preview-server.js` при слиянии (в т.ч. правило фильтрации рецептов). Это дублирование кода
  специально: клиент должен уметь сам нормализовать данные независимо от того, какой сервер ответил.
- **Русский текст описаний способностей/предметов** — в обоих серверах одинаковый набор функций
  (`parseVdfTokens`/`buildAttribMap`/`fillPlaceholders`/`hasUnresolvedPlaceholder`/`getOfficialRuMap`/
  `resolveRuText`, имена намеренно совпадают) реализует цепочку источников: официальный русский текст
  Valve (см. «Официальный RU-текст» ниже) → DeepL → английский оригинал. Каждое описание получает поле
  `source` (`'official-ru' | 'deepl' | 'en'`), которое `js/app.js` показывает пользователю через
  `sourceLabel()`. Если меняешь эту логику в одном файле — обнови и второй.

**Правило:** если правишь `server.js` или `preview-server.js` — проверь, не разошлась ли логика с другим
файлом (особенно `normalizeItems`/`normalizeHeroes`/фильтры категорий). Расхождение незаметно копится и
именно так возникла часть багов, описанных ниже. Если меняешь фильтрацию/нормализацию данных в одном
файле — загляни в `js/app.js`, `preview-server.js` и `server.js` разом и обнови все три, если применимо.

## Как запускать локально

```
Open Dota 2 Helper.cmd
```
Поднимает превью-сервер на `http://127.0.0.1:4173` без Postgres/Redis — только для проверки статики и
прокси данных Dota. Проверка живости: `http://127.0.0.1:4173/api/health` → `ok: true, version: v43`.

Полный прод-стек (профили, стриминг, донаты) требует переменных из `.env` (см. `.env.example`) и
`docker compose up -d --build`.

## Стиль кода — ВАЖНО

Существующий код (особенно `server.js`, `js/app.js`) написан очень компактно: длинные однострочные
функции, минимум пробелов, без промежуточных переменных ради краткости. Это осознанный стиль автора.

**Правило:** при правке существующих файлов — следуй тому же компактному стилю, чтобы не превращать
файл в смесь двух почерков. Для НОВЫХ отдельных файлов можно писать более читаемо, если не просят иначе.
Не переписывай/не рефактори большие куски «заодно» без явной просьбы — в таком плотном коде это легко
что-то незаметно сломает.

## Безопасность — нельзя нарушать

- `.env` и всё содержимое `secrets/` никогда не коммитятся и не выводятся в чат целиком.
- `JWT_SECRET`, `TURN_SECRET`, ключи CloudPayments — только через переменные окружения/секреты,
  никогда не хардкодить и не передавать в браузер.
- Stream key канала — секрет владельца канала, не логировать и не вставлять в открытые страницы/доки.
- CSP настроен в `securityHeaders()` в `server.js` (`server.js`, строка со `Content-Security-Policy`).
  **Любой новый внешний скрипт (рекламная сеть, аналитика, виджет) требует добавления его домена в CSP**,
  иначе он молча не заработает в браузере — не забывай про это при добавлении рекламы/аналитики.
- CSRF-токен и Origin-проверка уже реализованы для всех небезопасных методов — не отключать ради
  «упрощения» отладки.

1. `node --check server.js`, `node --check preview-server.js`, `node --check security.js`, `node --check js/*.js`

## Контент-статьи (guides/)

С сентября 2026 в проекте есть папка `guides/` — отдельные статические HTML-страницы с полноценными статьями
(не путать с короткими карточками-подсказками в `guideData` внутри `js/app.js` — это разные вещи).
Каждая статья в `guides/` — самостоятельная страница с своим `<title>`, `<meta description>`, OG-тегами и
`rel=canonical`, подключается через `../css/style.css` и переиспользует класс `.article-body` для типографики.
Ссылки на статьи добавляются вручную в блок `.guide-articles-grid` в разделе «Гайды» на `index.html`, а сама
статья — в `sitemap.xml`.

Принцип содержания статей: только эволюционирующие/вечнозелёные темы (роли, варды, принципы драфта, принципы
итемизации), без конкретных цифр баланса/цен/кулдаунов, которые меняются от патча к патчу — за актуальными
цифрами статьи ссылаются на живые разделы сайта (`#heroes`, `#items`, `#meta`, `#builds`), которые тянут данные
из API. Так статьи не устаревают вместе с патчами Dota 2.

При добавлении новой статьи: создать `guides/<slug>.html` по образцу существующих файлов, добавить карточку в
`.guide-articles-grid` на `index.html` и строку в `sitemap.xml` (домен там пока плейсхолдер
`YOUR-DOMAIN.example` — заменить после покупки домена/хостинга, поиском по всему проекту).

## Монетизация и рост (контент + реклама/партнёрки)

Когда просят добавить рекламу, партнёрские блоки, аналитику или новый контент (гайды, лендинги):

- SEO: у каждой значимой страницы должны быть уникальные `<title>` и `<meta name="description">`
  (уже частично сделано на index.html — держи такой же паттерн для новых страниц/гайдов).
- Скорость: реклама не должна блокировать рендер страницы — грузить асинхронно/отложенно (`async`/`defer`,
  lazy-load для баннеров ниже первого экрана).
- Партнёрские ссылки помечать `rel="sponsored"` (важно для Google) и по возможности явно подписывать
  «партнёрская ссылка» рядом — это и требование площадок, и вопрос доверия аудитории.
- Не размещать интерстишлы/попапы, перекрывающие контент на мобильных — это бьёт и по SEO, и по удержанию.
- Не забывать про CSP (см. раздел «Безопасность») при подключении рекламных/аналитических скриптов.
- Донаты через CloudPayments уже есть — это тоже канал монетизации, отдельный от рекламы.

## Технические долги — статус на 16.09.2026 (см. AUDIT.md)

Решено 16.09.2026 (сессия 1 — перенос эндпоинтов + DeepL):
- В `server.js` добавлены `/api/dota/item/:id`, `/api/dota/hero/:id/items`, `/api/dota/hero/:name/abilities`
  (были только в `preview-server.js`) — с кэшированием в Redis (fallback на in-memory Map, если Redis
  недоступен, по тому же паттерну, что и `rateLimit`).
- Добавлен `translateToRu()` (DeepL API, ключ — `DEEPL_API_KEY` в `.env`, см. `.env.example`) с кэшем
  переводов в Redis на 90 дней (в `preview-server.js` — на диске). Если ключ не задан или DeepL
  недоступен — сайт молча показывает оригинальный английский текст, ничего не ломается.
- `js/app.js`: `openHero` асинхронно тянет реальные способности с сервера вместо статичных подписей;
  `openItem` показывает пометку «переведено автоматически» / «текст на английском» рядом с описанием.

Решено 16.09.2026 (сессия 2 — багфиксы после первого реального использования):
- **Баг:** в `preview-server.js` не было `require('crypto')`, а `translateToRu()` вызывал
  `crypto.createHash()` — падало на КАЖДОМ запросе. Из-за этого не работали одновременно описания
  предметов И способности героев (это и была причина «не увидел описаний вообще»). Исправлено —
  добавлен `const crypto = require('crypto');` в начало `preview-server.js`.
- **Баг:** `normalizeItems()` (и в `preview-server.js`, и в `js/app.js`) молча выбрасывал **все** предметы
  типа «рецепт» (`item_recipe_*`). Рецепты — реальные покупаемые предметы Dota 2 со своей ценой и иконкой,
  и на `index.html` уже есть готовый фильтр категории «Рецепты» — он всегда показывал «Предмет не найден»,
  потому что данные до него просто не доходили. Это и было причиной «предметов в Dota 2 больше, чем
  показывает сайт»: полный официальный список Valve — 544 предмета (415 обычных + 129 рецептов), сайт
  показывал только 415. Исправлено — фильтр по рецептам убран из `normalizeItems` в обоих файлах, рецепты
  теперь остаются в данных и корректно попадают в категорию «Рецепты» через `itemCategory()`.
- Добавлены прямые ссылки в главное меню (все 6 страниц) на Build Lab (`#builds`), Match Assistant
  (`#match-assistant`) и Draft Assistant (`#draft`) — раньше были доступны только через прокрутку/поиск.
- **Баг (подтверждено «да» на правку `server.js`):** `dotaProxy` для `/api/dota/items` отдавал **сырой**
  ответ OpenDota как есть. Объекты OpenDota `constants/items` не содержат поля `name` (только `dname` и
  внутренний ключ вроде `"blink"` — сам `name` нужно брать из ключа объекта). Клиентский
  `normalizeItems()` требует `raw.id && raw.name` — без слияния/восстановления `name` каждый предмет
  отбрасывался этой проверкой, то есть после реального деплоя (не через `Open Dota 2 Helper.cmd`, а через
  `server.js`) список предметов на сайте оказался бы пустым. Исправлено — `dotaProxy` теперь делает то же
  слияние Valve → OpenDota → dotaconstants, что и `preview-server.js` (те же имена функций
  `normalizeItems`/`mergeItems` специально, для единообразия — см. «Карта данных» выше), с кэшем в Redis
  на 6 часов. Путь `/api/dota/heroes` не трогал — у OpenDota `heroStats` поле `name` уже есть, там бага не
  было.

Решено 16.09.2026 (сессия 3 — официальный RU-текст Valve вместо DeepL как основной источник):
- **Официальный RU-текст.** По просьбе — найден и подключён бесплатный источник настоящих русских
  описаний способностей и предметов от самой Valve: репозиторий `dotabuff/d2vpkr` на GitHub
  (`dota/resource/localization/abilities_russian.txt`) — это автоматически извлекаемые из реальных файлов
  игры (VPK) локализационные тексты, обновляются при каждом патче, без каких-либо API-ключей. В движке
  Dota 2 предметы внутри — это тоже «abilities» с префиксом `item_`, поэтому один и тот же файл содержит
  тексты и для героев, и для предметов. Токен способности —
  `DOTA_Tooltip_ability_<internal_key>_Description`, предмета —
  `DOTA_Tooltip_ability_item_<internal_key>_Description` (`internal_key` — тот же ключ, что в объектах
  OpenDota `constants/hero_abilities`/`constants/abilities`/`constants/items`).
- Сырой текст токена содержит `%placeholder%` (например `%blink_range%`) — они заполняются из `attrib`
  самой способности/предмета (те же данные, что уже приходят от OpenDota).
- Проверено на реально скачанном файле локализации (без live-запроса из-под Claude, см. ограничение
  ниже): официальный RU-токен нашёлся для ~99.7% способностей героев и ~95–96% предметов (после
  подстановки плейсхолдеров). Также подтверждено: Valve в русской локализации не переводит собственные
  имена (Blink Dagger и т.п. остаются как есть) — это совпадает с тем, как уже был написан сайт.

**Обновлено 16.09.2026 (сессия 4 — убрали DeepL и English-фолбэк, русский язык теперь единственный):**
по прямой просьбе пользователя цепочка `официальный RU → DeepL → английский` упрощена до одного шага:
- `resolveRuText(internalKey, isItem, attribArr)` (сигнатура изменилась — `fallbackEn` больше не
  принимает) теперь либо отдаёт официальный RU-текст (токен найден и все `%placeholder%` подставлены),
  либо `{text:'', source:'none'}` — без вызова DeepL и без показа сырого английского текста. Пустая
  строка не требует отдельной обработки на фронтенде: там уже были готовые нейтральные заглушки
  («Описание пока недоступно.» для способностей, «Описание отсутствует в официальном feed.» для
  предметов) — они и подхватывают этот случай сами.
- `translateToRu()`, `DEEPL_API_KEY`/`DEEPL_API_URL`, `localTranslateFallback` — полностью удалены из
  `server.js` и `preview-server.js` (не использовались больше нигде, кроме этой цепочки). Строка
  `DEEPL_API_KEY=` убрана и из `.env.example`. Если реальный ключ всё ещё лежит в `.env` на вашем
  компьютере — он просто не используется, можно оставить как есть или удалить вручную.
- `getItemDetail`/`getItem` (описание предмета) теперь перезаписывают и `desc_loc`, и `description`
  результатом `resolveRuText` (или пустой строкой) — раньше `description` мог остаться со старым
  английским значением из ответа Valve datafeed и просочиться на экран в обход перевода через `||`
  в `js/app.js`; теперь оба поля синхронизированы.
- **Кэш файла локализации теперь общий для обоих серверов принцип «весь файл — раз в неделю»:**
  `getOfficialRuMap()` кэширует файл `abilities_russian.txt` на 7 дней (было 24ч в `server.js`, 12ч в
  `preview-server.js`) — Redis (`dota:vdf-ru:v2`) в проде, диск (`vdf-ru`) в превью. Первый показ сайта
  после старта сервера (или после недели простоя кэша) тянет свежий файл с GitHub, все последующие
  показы — из кэша, без сетевого запроса. Отдельный per-ability Redis-кэш `ability-ru:v2:*` (90 дней)
  убран как избыточный: без DeepL резолвинг — это просто поиск в уже закэшированной карте и подстановка
  чисел, кэшировать это отдельно незачем.
- `js/app.js`: метки-подсказки об источнике перевода («Официальный текст Valve (RU)» / «Переведено
  автоматически» / «Официальный текст (EN)») убраны из интерфейса ещё раньше в этой же сессии (отдельная
  просьба пользователя — они бесполезны для читателя); поле `source` в ответах API осталось только для
  внутренней диагностики (`'official-ru'` или `'none'`).
- Английская версия сайта (без API-ключей) запланирована на будущее отдельной задачей — этот рефактор
  её не блокирует: `resolveRuText` можно будет позже расширить вторым словарём токенов
  (`abilities_english.txt` уже используется как источник самих ключей/списка способностей).
- **Живая проверка качества текста на сайте** — из-под Claude нельзя надёжно получить live сетевой ответ
  (см. ограничение ниже); финальную проверку, что реальные описания подтягиваются с d2vpkr и выглядят
  корректно, может сделать только сам пользователь через `Open Dota 2 Helper.cmd`.

**Ограничение проверки, которое стоит знать на будущее:** в среде, где работает Claude (и в облачном
контейнере, и в командной строке на вашем компьютере через `device_bash`), сетевые вызовы из Node.js
(`fetch`, `https.get`) идут в обход прокси, через который здесь разрешён внешний интернет, и падают с
`EAI_AGAIN`/таймаутом, даже когда те же самые адреса прекрасно открываются через `curl` в той же
командной строке. Это особенность именно инструментов Claude, а не вашего компьютера или сайта — при
обычном запуске `Open Dota 2 Helper.cmd` (двойным кликом, не через Claude) Node ходит в интернет напрямую
и никаких прокси не видит. Практический вывод: результаты типа «получил реальные данные от Valve/OpenDota/
DeepL» из-под Claude могут на самом деле означать «прочитал старый дисковый кэш, потому что живой запрос
незаметно упал». Финальную проверку по-настоящему живых данных (особенно перевод DeepL и способности
героев) может сделать только сам пользователь, открыв сайт после `Open Dota 2 Helper.cmd` в браузере.

Ещё не сделано:
- Для ~4-5% предметов и ~0.3% способностей героев, где у Valve нет официального RU-токена (или в тексте
  остаётся нерешённый `%placeholder%`), описание сейчас пустое (показывается нейтральная заглушка вместо
  текста) — начиная с сессии 4 сайт сознательно не подставляет туда ни DeepL, ни английский оригинал.
  Если это станет заметно мешать, варианты на будущее: ручные RU-описания для этих конкретных карточек,
  либо вернуть DeepL точечно только для них.
- Англоязычная версия сайта без платных API-ключей — отдельная задача на будущее (см. «сессия 4» выше).

- Формулируй запрос как для коллеги, который уже читал этот файл: не нужно каждый раз пересказывать,
